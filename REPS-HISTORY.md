## CHANGELOG-APPLE-WATCH-2026-10-27

Original file: `CHANGELOG-APPLE-WATCH-2026-10-27.md`

# Apple Watch companion — build 70

Added a native single-target watchOS companion (watchOS 10+) embedded in the iPhone app. The iPhone remains the authority for training data. No SwiftData schema or existing workout identifiers changed.

## Available on Watch

- List available routines and start one, using the same planning, past performance, gym and routine-link logic as iPhone.
- View the active workout, elapsed time, current exercise and exact next set or drop stage.
- Edit simple strength-set weight with the Digital Crown and adjust reps; the iPhone confirms each save.
- Complete a set/stage, view overall set progress and rest countdown, add 15 seconds or skip rest.
- Foreground rest haptics and optional local rest alerts, with notification permission requested only from the Enable rest alerts button.
- Confirm finish, save completed sets to the original iPhone workout and see its summary. Existing iPhone Health-writing preferences continue to apply.
- Selected iPhone theme and kg/lb preference carry across to Watch.

Settings → Apple Watch describes setup and shows pairing/app-install/connectivity status.

## Sync and recovery

Explicit versioned snapshots exclude account tokens, private notes and media. Immediate WatchConnectivity requests carry the displayed revision, workout, movement and exact action ID. The phone rejects stale, malformed, out-of-range or signed-out actions. Duplicate request IDs cannot advance a second set. Finish confirmation also retains its original workout/revision. Commands are never queued for later replay while disconnected. Timeouts tell the user to refresh and check the saved workout before retrying.

Phone actions publish fresh snapshots, including sign-out, changes to routines, theme, units, live set edits and finished workouts. A workout open on iPhone reloads remote changes and opens its summary when finished from Watch. Routine creation was extracted without changing its planning logic.

## Verification

- Watch simulator build 70 passed.
- iPhone simulator build passed. The original controller checks ran in the iPhone simulator with an in-memory training database.
- DEBUG-only in-memory controller regression checks passed for start, request deduplication, stale revisions, invalid inputs, completion/volume, rest controls, finish, drop stages, sign-out privacy and wire encoding.
- Device build 70 passed after the user signed into Xcode. Deep signature verification passed. Installed on Harsha’s Phone and independently verified version 0.11.0 / build 70.
- The original iPhone fixture displayed the passing checks and its synthetic routine. Watch app presence inside the iPhone bundle and its companion bundle ID were verified.
- Native Watch screen and paired WatchConnectivity acceptance remain pending: the task-owned Watch simulator stalled in Apple system migration on three boots (Launch Services, Managed Configuration, then Siri). It never reached a testable Watch app screen; no Watch UI or paired-transport pass is claimed.
- Build 70 uses the same workout controller as the passing regression run; its Watch accent was adjusted to the main app’s light accent shade for readable dark-surface contrast.

## Scope before TestFlight

This is a nearby-iPhone companion. It does not yet implement phone-free workout recording, a live HealthKit workout session/heart-rate collection on Watch, complications or Smart Stack widgets. Real paired Watch hardware testing remains required for connection recovery, wrist-down rest notifications and haptics.

The user confirmed no paired physical Apple Watch is available. Both task-owned simulators were shut down after testing to release memory; they were retained for another validation attempt.

## CHANGELOG-CUSTOM-ALERTS-2026-10-26

Original file: `CHANGELOG-CUSTOM-ALERTS-2026-10-26.md`

# Reps Pro custom alerts — build 64

Custom alerts are available at Profile → Reps Pro → Custom alerts, Pro Training, and Settings → Notifications & Lock Screen. Creating, editing and enabling alerts requires the existing signed-in Pro entitlement; the feature does not change subscriptions or grant access.

Each alert has a name, optional message, local time, one-time/daily/selected-weekday schedule, and a sound. Three original short PCM tones (Soft chime, Pulse, Bright) are bundled alongside Default and Silent. Bundled tones can be previewed. Sounds follow iPhone sound and Focus settings.

An alert can optionally link to one saved routine or folder. Notification taps open the routine detail or folder without automatically starting a workout. Unlinked alerts open the alert list. Missing links produce a recoverable message. Routine starts from the notification detail wait until its sheet is dismissed.

Alerts are stored locally under separate account keys. Notification permission is requested when needed to save an enabled alert. Denied permission shows an iPhone Settings shortcut. Alerts can be paused, edited and deleted; past one-time reminders are not rescheduled. App/account/entitlement refreshes reconcile the custom-alert request namespace and cancel it when Pro is unavailable or the user signs out. These are local reminders, with no backend or cross-device sync.

Scheduling validates titles, weekday choices, duplicate identifiers and available request capacity. Stable identifiers replace edited requests. Failed saves restore the previous saved schedule. Custom requests reserve capacity for rest timers; disabling rest alerts now removes only rest notifications. English/Tamil copy and the Pro benefits comparison include the feature.

Validation results are recorded with the task screenshots and build logs. Real delivery on the connected phone requires notification permission and a user-created alert; no test reminders are created on the phone during installation.

Device/simulator builds, signature verification, alert logic checks, native trigger/resource checks, existing Home/Settings/tour regressions, and light/dark/large-text/Tamil visual checks all passed.

Installed build 64 on Harsha’s Phone (iPhone 14 Pro Max). The first connection attempt reset; the retry succeeded.

Primary Desktop Reps project.

## Reproduced launch failure

Normal launch of the installed phone app terminated with signal 5 and:
`SwiftUICore/EnvironmentObject.swift:93: Fatal error: No ObservableObject of type ExerciseLibrary found.`

The ExerciseLibrary environment modifier was attached to the inner TabView before additional presentation hosts. Moved it to ContentView's outermost view chain, above all tab, alert and sheet hosts. ## Repeated workout processing

Home, Progress, workout rows and widgets repeatedly call movements(), previously creating a JSONDecoder for the same saved exercise blob on every read. Added two bounded NSCache instances for decoded routine/workout arrays. Cache keys use actual immutable blob bytes, so edits, imports and direct restore replacements are reflected immediately, even if updatedAt is unchanged. Arrays preserve copy-on-write behavior. Cache eviction only reintroduces decoding; no persistent storage fields or formats changed. Each cache permits 256 entries with a 16 MB estimated-cost limit.

A focused current-model regression executable checks returned-array isolation, movement updates, total volume, direct blob restoration, corrupt data recovery, routine changes and in-memory SwiftData save/fetch. A 12-exercise × 8-set fixture with 2,000 repeated reads measured 1,964.5 ms uncached vs 7.1 ms cached in an unoptimized local run. This is a microbenchmark, not a whole-app frame-rate or phone-latency measurement.

Final validation: combined launch/cache repair signed build passed and installed over the existing app. The user confirmed: “it opens normally.” A repeat microbenchmark measured 1,597.4 ms uncached vs 6.3 ms cached. ### Share and schedule

- Share Routine exports a `.repsroutine` file using the iOS share sheet (AirDrop, Files or another destination selected by the user).
- Reps registers the file type. Received files open a preview, then Add to Routines. Titles, creator credit, exercises, rep targets, set types and superset groups are preserved; logged sets, workout notes and Health data are absent.

- Routine → Calendar prepares an Apple Calendar event for review. Choose start, duration, weekly repetition and reminder. Saving is performed by the user in Apple's editor; Reps does not request access to read other events.
- Locally saved Calendar references prevent the same schedule being added twice on the same device. This is one-way scheduling, not automatic/two-way calendar synchronization. Edit or delete a saved event in Apple Calendar. References are scoped per app installation.
- CSV import previews workouts before saving, skips duplicates and validates all rows first. Supports Reps exports and compatible Hevy/Strong-style headers when the required date, name, exercise, kilogram weight and reps fields exist.
- UTF-8 CSV only. Quoted commas/newlines are supported; unsupported dates/numbers/set types are reported. Files without finish times retain an unknown duration; Reps does not invent duration, muscle group, energy or heart rate. Actual superset links cannot be reconstructed from a CSV set-type label alone.
